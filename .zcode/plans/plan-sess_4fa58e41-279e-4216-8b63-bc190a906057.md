# 支持内存/显存预算的专家按需加载（层级驻留 + 槽位管理）

## 现状（探索结论）

代码已有一套按需加载：`--moe-backend offload`（MoE 模型默认）把全部专家 pin 进 CPU pinned 内存（HostBank），GPU 侧用 flashlib LRU 槽位缓存按 PCIe 拉取（`OffloadMoeCache`，slot_for_id/id_of_slot/usage 槽位表齐全，支持运行时 resize 与命中率统计）。真正的缺口：

1. **CPU 内存无上限**：所有专家强制 pin（≈checkpoint 大小），装不下直接失败；
2. **显存只有比例**（`--memory-ratio` 0.9），无绝对预算；
3. `HostResidency`（PINNED/PAGEABLE）扩展点已预留但 `set_bank_sources` 直接 raise（offload_cache.py:291）。

## 用户可见行为

- `--gpu-mem 16G`：绝对显存预算（权重 + MoE 槽位 + KV 池三者之和的上限；CUDA graph/激活不在此限，超限启动时打警告）。与 `--memory-ratio` 互斥。在预算内 MoE 优先解出槽位数与 KV 页数（复用 `plan_cache_budget`）。
- `--cpu-mem 32G`：CPU 内存预算，**层级驻留**——预算内的层照旧 pin（GPU 快路径），装不下的层改为**文件后备**（tmpfile + mmap MAP_SHARED，填充后 `madvise(MADV_DONTNEED)` 丢页，CPU 侧访问按需从磁盘缺页读入，OS 页缓存天然做 LRU）→ 这些层强制加入 `cpu_layer_ids`，decode 走现有 CPU executor（GEMV），即"从 CPU/磁盘按需加载"。默认全部 pin（行为不变）。
- 槽位管理上报：`/v1/cache/status` 增加 host 侧字段（pinned 字节/预算、文件后备层数、spill 目录），`ft ctl cache` 渲染新增 Host 段；启动日志打印预算规划结果。

## 实现

### A. 显存绝对预算 --gpu-mem
- `env.py:_PARSE_MEM_BYTES` 提为公共 `parse_mem_bytes`，作 argparse type（"16G"/"512M"/裸字节数）。
- `server/args.py`：`--gpu-mem` 加入与 `--memory-ratio` 的互斥组；`ServerArgs`/`SchedulerConfig`/`EngineConfig`（engine/config.py）加 `gpu_mem_budget: int | None = None`（dense 模型也生效，仅限 KV 预算）。
- `engine/engine.py`：
  - `_resolve_auto_moe_cache_size`（:469）：budget 来源改为 `gpu_mem_budget - weights - fixed`（绝对模式）或现有 ratio 公式；
  - KV 启动 sizing（:343 `_startup_kv_budget`）：绝对模式 `available = gpu_mem_budget - (init_free - new_free) - state_pool`；新增纯函数分支便于测试；
  - 初始化完成后校验实际占用，超预算打 warning。

### B. 内存预算 --cpu-mem（层级驻留）
- `engine/cache_budget.py` 新增纯函数：
  - `estimate_layer_bank_bytes(model_config)`：按 expert_quant 格式估算每层 bank 字节（ drift 防护：测试断言 ×num_experts 与 `expert_bytes_per_slot(dummy)` 一致）；
  - `plan_host_residency(num_layers, layer_bytes, budget) -> list["pinned"|"file"]`：贪心 pin 至预算。
- `moe/host_banks.py`：`HostBank` 增加 `backing="anon"|"file"`（file 模式：model 目录下 tempfile→ftruncate→mmap MAP_SHARED→立即 unlink，进程退出自动回收磁盘）；新增 `drop_pages()`（file 专用 MADV_DONTNEED，数据可从文件重读）；`PinPipeline(pin_layers=None)` 过滤；`alloc_layer_banks(backing=...)`。
- 加载链路穿参 `layer_backing: list[str] | None`（None=全 pin，今日行为）：`expert_banks.py:load_expert_banks/_build_expert_banks`（inspect 参数探测处 :316 补 `layer_backing`）→ 各 provider/加载器（weight.py、loader.py、ftw.py、nvfp4_banks.py、gpt_oss/weight.py、gemma4/gguf.py、deepseek_v4/weight.py、qwen3_5_moe/weight.py）机械透传到 alloc/PinPipeline。
- `moe/offload_cache.py`：
  - `set_bank_sources` 接受 PAGEABLE 层（移除 :291 的 raise），记录 `layer_residency`；
  - `_build_copy_plan`：逐层探测 `device_ptr`，失败层标记 fused-unsupported（`_copy_fused_ok` 改为逐层）；
  - `copy_missing`：pending 层为 file-backed 时走 torch 回退（`cache[dst]=src[idx]`，prefill-only 路径，允许同步）。
- `engine/engine.py:_init_offload_moe_cache`：预算→`plan_host_residency`→传给 loader；`cpu_layer_ids = 用户指定 ∪ file-backed 层`（`_resolve_cpu_layers` 返回后合并）；一致性断言（file-backed ⊆ cpu_layer_ids）；日志打印层级切分。预算生效时 bank 布局自然走 native（decode_target 变 "cpu"），GPU 层继续用槽位缓存 GEMM。

### C. 槽位管理上报
- scheduler 的 cache status meta 增加 `gpu_budget_bytes / host_pinned_bytes / host_budget_bytes / host_file_backed_layers`；`cache_report.py` 渲染 Host 段（`format_bytes` 已有）。
- `docs/cli.md` 补两个 flag；`docs/model-loading.zh.md` §2.6、`docs/inference.zh.md` §5.3 补简短说明。

- `tests/moe/test_host_banks.py`（新）：file-backed HostBank 填充→drop→重读一致；alloc_layer_banks 预算切分。
- `tests/moe/test_offload.py`：混合 residency 的 set_bank_sources；copy_missing 文件后备回退正确性（CPU 设备可测）。
- args 解析：`--gpu-mem 16G`、互斥报错。

## 已知限制（写入文档）
- file-backed 层 decode 在 CPU（GEMV），首次 prefill 走页缓存较慢；nvfp4 在混合驻留下 GPU GEMM 用 triton 后端（非 marlin）；`--cpu-mem` 仅启动时生效（不支持运行时重规划）；spill 文件占用约等于未驻留专家大小（默认 model 目录）。

不涉及任何 C++/CUDA 重编译；全部为 Python/Triton 层改动。
